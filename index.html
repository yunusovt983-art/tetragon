Kernel Event Ingestion

supporting domain

Владеет eBPF-программами и циклом чтения userspace: поднимает сырые события (execve, fork, exit, kprobe) из ring/perf buffer'а в типизированные Go-события. pkg/observer, pkg/sensors, bpf/*.c.

Tracing Policy

supporting domain

Компилирует пользовательскую политику (CRD/YAML) в байткод селекторов ядра — «движок правил» системы. pkg/tracingpolicy, pkg/selectors, pkg/policyfilter.

Process Domain

core domain

Главный агрегат всей системы — дерево живых процессов в памяти с GC, обогащённое credentials, namespaces и метаданными пода. pkg/process (ProcessInternal), pkg/eventcache.

K8s Integration

generic subdomain

Anti-corruption layer между Kubernetes API и доменом процессов — переводит corev1.Pod в собственные tetragon.Pod. pkg/k8s, pkg/watcher, pkg/manager.

API / Application

interface · open host service

Единственный поддерживаемый вход/выход агента. Переводит сырые сообщения ядра в published language (tetragon.* proto) и раздаёт по gRPC. pkg/server, pkg/grpc.

Export Pipeline

generic subdomain

Downstream-потребитель API-контекста — переигрывает тот же поток GetEvents in-process, пишет отфильтрованный JSON на диск. pkg/exporter, pkg/fieldfilters.

Operator

generic subdomain · отдельный деплоймент

Отдельный бинарь, cluster-scoped, с leader election. Регистрирует CRD и реконсайлит только PodInfo — реконсиляция TracingPolicy переехала в сам агент, per-node.

tetra CLI

interface · client

Тонкий gRPC-клиент плюс Linux-only команды локальной диагностики хоста, часть из которых работает без единого запущенного агента (раздел «tetra CLI» ниже).

от ядра до JSON
1
bpf_execve_event.c ядро

execve() перехвачен на tracepoint-хуке, событие упаковывается в ring buffer — решение «интересно ли это» уже принято здесь, до выхода из ядра.

2
pkg/observer userspace, Go

Читает сырые байты из ring/perf buffer, диспетчерит по опкоду.

3
pkg/process core domain · aggregate root

Создаёт/обновляет запись в GC'd LRU-кэше процессов; обогащает через watcher.PodAccessor — anti-corruption layer к Kubernetes API.

4
pkg/eventcache retry-координация

Если метаданные пода ещё не подъехали от k8s-информера — ждёт до 15 тиков по 2с, затем best-effort эмитит событие без полного обогащения.

5
pkg/server → gRPC / JSON interface · OHS

Стримит внешним gRPC-клиентам и/или пишет отфильтрованный, редактированный JSON на диск через pkg/exporter.

Ключевые находки

не только «как устроено», но и «где болит»

pkg/aggregator — мёртвый код

Механизм агрегации событий полностью встроен в конвейер, но handleEvent() содержит только default-ветку — каждое событие пересылается без изменений. Подтверждено трижды независимо (ручная проверка + 2 research-прохода).

Асимметрия привилегий

Агент — privileged: true на ноде, но read-only в k8s RBAC. Оператор — без привилегий на ноде, но CRUD-доступ и владение определениями CRD. Инверсия по двум осям одновременно.

matchPIDs: writer/reader асимметрия

Go может записать несколько PID-условий подряд; C-читатель — не цикл, а одно if, читает ровно одну запись. Найдено чтением исходников рядом, не подтверждено запуском.

Честная модель угроз

«No security observability data from a root-compromised node can be considered trustworthy» — проект прямо признаёт границу своих гарантий, а не маскирует её.

mTLS не покрывает метрики и health

pkg/certloader используется ровно в одном месте — основном gRPC API. Prometheus-эндпоинт и health-check всегда открытым текстом, без флага и без кода, который мог бы это изменить.

Два несвязанных rate limiter'а

Per-selector действие RateLimit (дебаунс по timestamp) и cgroup_rate() (скользящее окно для execve/fork) — независимые механизмы. А pkg/ratelimit — вообще третья, не относящаяся к делу вещь: троттлинг gRPC-экспорта.

Суть — метод Фейнмана

объяснение без жаргона

Сервер — это дом, процессы в контейнерах — комнаты со своими жильцами. Нужно знать, кто заходит куда, и если кто-то хозяйничает не там — остановить сразу, а не после.

Камера + запись, которую смотрят вечером — узнаёшь о краже вечером. Охранник, обыскивающий вообще всех — ловит воров, но и мама, и почтальон стоят в очереди. Умный замок, который за миллисекунду чувствует отмычку и не открывается — решение принимается прямо в механизме двери, то есть в самом ядре ОС. Технология называется eBPF. tetragon — третий вариант.

Цимес одной фразой: обычно «следить за всем» и «мгновенно останавливать плохое» — два разных, дорогих инструмента. У tetragon оба свойства получаются из одной и той же вещи — решения, вынесенного внутрь самого ядра.

Метод «2 мозга»

независимые прочтения + сверка

Там, где цена независимого подтверждения выше накладных расходов на второй проход: два агента читают код заново, не видя друг друга и не видя черновиков этого текста, затем результаты сверяются построчно.
